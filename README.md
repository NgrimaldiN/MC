# Control Variates for Bayesian GARCH Estimation

This project implements **zero-variance control variates** to reduce the
Monte Carlo error of MCMC estimators for a Bayesian GARCH(1,1) model.
A random-walk Metropolis sampler targets the posterior of the GARCH
parameters; polynomial control variates in the score direction are then
used to deflate the variance of posterior mean estimates.  The approach
is validated on both simulated and real (EUR/USD) return data.

## Problem Statement

Bayesian estimation of GARCH models relies on MCMC, whose posterior mean
estimates carry non-negligible Monte Carlo error.  **Zero-variance (ZV)
control variates** (Mira, Solgi & Imparato 2013) exploit the gradient of
the log-posterior to construct a regression-based correction that lowers
the variance of the estimator.  The key questions addressed:

- How much variance reduction do first-order and higher-order polynomial
  controls provide?
- Does the full polynomial dictionary become numerically unstable at
  higher degrees, and can **Lasso screening** (Leluc, Portier & Segers
  2021) mitigate this?
- How does MCMC dependence affect the regression-based control-variate
  estimator, and what practical fixes help?

## Data

| Dataset | Description | Source |
|---|---|---|
| **Simulated GARCH** | 600 returns from GARCH(1,1) with ω=(0.04, 0.08, 0.88) | Generated internally (`garch_cv.simulate_garch`) |
| **EUR/USD** | 511 daily log-returns (2023-01-01 to 2024-12-31), in percent | [Frankfurter API](https://www.frankfurter.app), downloaded via `scripts/download_eurusd.py` |

The EUR/USD CSV is stored locally in `data/eurusd_frankfurter_2023_2024.csv`
(~9 KB).  It can be regenerated by running the download script.

## Method

### Model

Gaussian GARCH(1,1):

```
r_t | F_{t-1} ~ N(0, h_t),   h_t = ω₁ + ω₂ r²_{t-1} + ω₃ h_{t-1}
```

with truncated normal priors enforcing `ω₁>0, ω₂>0, ω₃>0, ω₂+ω₃<0.995`.

### Sampler

- **Random-walk Metropolis** on an unconstrained reparametrization
  θ→ω (exp/softmax transform with Jacobian).
- **Pilot tuning**: diagonal proposal scale first, then full-covariance
  proposal estimated from a pilot chain.
- **10 independent chains**, 8000 iterations, burn-in 2000, thinning 3.

### Control variates

| Method | Description |
|---|---|
| MC | Raw posterior mean (no controls) |
| ZV-OLS-1 | First-order polynomial controls (3 controls) |
| ZV-OLS-2 | Up to degree-2 polynomial controls (9 controls) |
| ZV-OLS-5 | Up to degree-5 polynomial controls (55 controls) |
| ZV-Lasso-5 | Lasso-screened degree-5 controls, then OLS refit on selected subset |

The Lasso implementation uses coordinate descent with BIC-based penalty
selection (no scikit-learn dependency).

### Numerical error assessment

- **Repeated independent chains**: 10 chains per dataset; the standard
  deviation of the final estimate across chains is the empirical
  numerical error.
- **Batch-means standard errors**: computed on the controlled output
  series for each chain.

### MCMC dependence study

A separate script (`scripts/mcmc_regression_dependence.py`) investigates
the impact of autocorrelation on the OLS regression used to estimate
control-variate coefficients.  It compares four approaches: naive same-chain
OLS, split-chain (fit on first half, evaluate on second), thinned OLS, and
block-means OLS.

## Results

### Variance reduction (simulated data)

| Parameter | MC sd | ZV-OLS-1 sd | ZV-OLS-2 sd | ZV-OLS-5 sd | ZV-Lasso-5 sd |
|---|---|---|---|---|---|
| ω₁ | 0.00265 | 0.000862 (9.4×) | 0.000389 (46×) | 0.0000405 (4258×) | 0.000121 (475×) |
| ω₂ | 0.00227 | 0.000721 (9.9×) | 0.000184 (152×) | 0.0000181 (15718×) | 0.0000454 (2501×) |
| ω₃ | 0.00390 | 0.000685 (32×) | 0.000370 (111×) | 0.0000382 (10461×) | 0.000135 (839×) |

Values in parentheses are variance reduction factors relative to MC.

### Variance reduction (EUR/USD data)

| Parameter | MC sd | ZV-OLS-1 sd | ZV-OLS-2 sd | ZV-OLS-5 sd | ZV-Lasso-5 sd |
|---|---|---|---|---|---|
| ω₁ | 0.00772 | 0.00772 (1.0×) | 0.00420 (3.4×) | 0.00215 (12.9×) | 0.00194 (15.8×) |
| ω₂ | 0.00326 | 0.00173 (3.5×) | 0.000951 (11.7×) | 0.00126 (6.7×) | 0.000762 (18.3×) |
| ω₃ | 0.04205 | 0.04088 (1.1×) | 0.02117 (3.9×) | 0.01041 (16.3×) | 0.01279 (10.8×) |

### Key observations

- On **simulated data**, ZV-OLS-5 achieves variance reductions of 4,000–15,700×,
  but the OLS design matrix becomes ill-conditioned (median condition number
  ~580,000).
- On **EUR/USD data**, variance reductions are more modest (1–18×).  ZV-OLS-5
  shifts the posterior mean of ω₁ from 0.082 to 0.075 and ω₃ from 0.483 to
  0.521, suggesting potential overfitting in the ill-conditioned full
  regression.
- **Lasso screening** keeps only 19–41 of the 55 degree-5 controls while
  still achieving substantial variance reduction, offering a practical
  compromise between dictionary size and numerical stability.

### MCMC dependence study

Block-means OLS (block size 80) reduces the lag-1 autocorrelation from
~0.85 (raw chain) to ~0.01, yielding variance ratios of 8–10× vs. raw MC.
Thinning (every 8) reduces autocorrelation to ~0.27 but gives smaller
variance improvement (6.5–7.7×).  Split-chain estimation is the most
conservative (3.2–6.2×).

## Limitations

- **Short real-data sample**: 511 daily observations (2 years).  GARCH
  models benefit from longer series for stable volatility estimation.
- **Ill-conditioning**: the degree-5 OLS design has condition numbers
  exceeding 10⁷ on real data.  Lasso mitigates but does not solve this.
- **Potential bias on real data**: ZV-OLS-5 shifts posterior means
  noticeably for ω₁ and ω₃, which may indicate overfitting in the
  full polynomial regression.
- **No formal convergence diagnostics**: the project relies on trace
  plots, running means, and repeated-chain agreement rather than
  R-hat or effective sample size metrics.
- **Custom Lasso**: the coordinate-descent Lasso is implemented from
  scratch without comparison to a reference implementation.
- **Single model family**: only Gaussian GARCH(1,1) is considered; no
  Student-t or asymmetric volatility models.
- **Limited repetitions**: 10 independent chains provide a rough but
  not exhaustive numerical-error estimate.

## Reproducibility

This project uses [uv](https://docs.astral.sh/uv/) for dependency management.

### Setup

```bash
uv sync          # Create virtual environment and install locked dependencies
```

### Re-run the analysis

```bash
# Execute the notebook (uses cached results by default; ~8 min if cache is stale)
uv run jupyter nbconvert --to notebook --execute --inplace control_variates_garch.ipynb

# Run the MCMC dependence study
uv run python scripts/mcmc_regression_dependence.py
```

To force a full re-run of all MCMC chains (instead of using the cache),
set `USE_CACHED_RESULTS = False` in the notebook's settings cell.

### Rebuild the report

```bash
pdflatex -interaction=nonstopmode -halt-on-error report.tex
pdflatex -interaction=nonstopmode -halt-on-error report.tex
```

### Refresh the data

```bash
uv run python scripts/download_eurusd.py
```
